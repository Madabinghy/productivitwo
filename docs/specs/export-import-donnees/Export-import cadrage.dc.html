NOTES TECHNIQUES

Ce que le code donne déjà

AppState.encode() produit déjà l'état complet en un JSON : l'export est ce fichier + un en-tête (schemaVersion, date, build, uid) et des compteurs pour l'écran d'aperçu. FirestoreSync merge par ID et le soft-delete est systématique : le mode Fusionner tombe naturellement du modèle existant — un élément absent du fichier ne supprime rien. Deux réserves : les programmes horaires sont un doc par jour (daily_schedules/{YYYY-MM-DD}), à sérialiser en section à part ; et les documents HTML sont volumineux, d'où l'option .zip. Les migrations one-shot (…MigratedOnce) doivent être rejouées après restauration, et un fichier au schéma supérieur être refusé proprement plutôt que décodé partiellement. Jamais dans le fichier : tokens API, secrets, consentements coach. La sauvegarde est un document utilisateur, pas un état d'authentification.

Prochaine étape utile : me dire si l'écran doit exister aussi côté web — le fichier étant le même, l'app web peut le télécharger sans travail supplémentaire.
